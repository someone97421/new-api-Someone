# 文件中转使用说明

文件中转将上游文件保存到 New API 所在服务器，并提供本站文件链接。目前自动中转覆盖非流式图片结果，以及首次访问时缓存的任务产物；不包括流式图片结果的自动转存。

## 快速启用

1. 在「系统设置 → 运维 → 文件中转」设置存储目录、公开站点地址和保留时间，开启「自动文件中转总开关」，保存。
2. 编辑需要中转的渠道，开启「自动文件中转」，保存。其他渠道保持关闭。
3. 通过该渠道生成图片，或首次访问该渠道任务的产物内容，系统才会自动保存文件。

**自动中转生效 = 全局总开关开启，并且当前渠道明确开启。**

| 全局总开关 | 渠道开关 | 自动中转 |
| --- | --- | --- |
| 关闭 | 任意状态 | 不生效 |
| 开启 | 未配置或关闭 | 不生效 |
| 开启 | 开启 | 生效 |

渠道开关默认关闭，没有「继承全局」选项。关闭全局总开关会阻止所有渠道新增自动中转文件，但不会清除各渠道已保存的开关状态；重新开启总开关后，明确开启的渠道恢复自动中转。

## 运维中的全局选项

| 选项 | 功能与默认值 |
| --- | --- |
| 启用直接文件上传 | 允许客户端使用现有 API Key 调用 `POST /v1/file-relay`，提交远程 URL、Base64 或文件进行主动转存。默认关闭，与自动中转总开关及渠道开关独立。只需自动中转时可保持关闭。 |
| 自动文件中转总开关 | 控制所有渠道是否允许新增自动中转文件。默认关闭；开启后仍需逐个渠道手动开启。 |
| 存储目录 | 服务器保存中转文件及元数据的位置，默认 `./data/file-relay`。Docker 中是容器内路径，需映射到持久化目录。更换目录不会自动搬迁旧文件。 |
| 公开站点地址 | 客户端访问文件所用的 HTTP(S) 站点基础地址，例如 `https://api.example.com`。留空使用系统的 `ServerAddress`；系统自动追加 `/v1/file-relay/content/:id`。地址应能被客户端访问。 |
| 文件保留时间（小时） | 默认 `168` 小时，即 7 天；`0` 表示永久保留。文件到期后不可再通过缓存链接读取，清理任务随后删除文件。修改此值影响之后保存的文件，不重算已有文件的到期时间。 |
| 清理间隔（分钟） | 默认 `10` 分钟，控制多久扫描并删除过期文件。关闭自动中转后仍会清理过期文件。 |
| 下载超时（秒） | 默认 `60` 秒，限制一次转存操作的下载等待时间，重试共用该时间预算。 |
| 下载重试次数 | 默认 `2` 次，范围 `0–5`；表示首次下载失败后最多额外重试几次。仅重试文件下载，不会重新调用模型生成。 |
| 默认要求本地托管（严格模式） | 默认关闭。关闭时，中转失败允许保留原始图片结果，或回退到上游任务内容；开启时，中转失败返回交付错误。已成功完成的生成仍正常计费，不因文件交付失败重新生成或退款。渠道可以覆盖此策略。 |

直接上传接口也使用全局存储、超时、重试和严格模式配置。宽松模式下，主动转存远程 URL 失败可以返回原 URL，并标记 `relayed: false`；Base64 或文件上传失败仍会报错。

## 渠道中的选项

| 选项 | 功能 |
| --- | --- |
| 自动文件中转 | 默认关闭。只有手动开启，且全局总开关也开启时，该渠道才会自动保存新文件。 |
| 要求本地托管（严格模式） | 「继承全局」使用运维的默认失败处理策略；「开启」要求本地托管成功，否则返回交付错误；「关闭」允许中转失败时回退。默认继承全局。这个选项本身不会开启自动中转。 |

跨渠道重试成功后，图片中转采用最终成功渠道的策略；任务产物按该任务所属渠道的策略处理。

## 旧配置与历史文件

- 原来未配置渠道开关，或选择「继承全局」的渠道，现在均按关闭处理，需要手动开启。
- 原来明确开启的渠道保留开启状态，但必须同时满足全局总开关开启。
- 更早的全局配置若没有自动中转字段，会暂用旧 `enabled` 值作为全局总开关初始值；渠道仍默认关闭。在运维页面保存后，自动中转与直接上传开关分别保存、独立控制。
- 关闭自动中转、关闭直接上传或删除渠道，不会主动删除已缓存文件。在存储目录不变、文件未过期且未被删除的前提下，已有缓存仍可读取；任务内容入口继续遵循原有访问要求。
- 自动中转关闭只影响新增本地副本，任务内容仍可能按原有方式从上游读取，不等于关闭任务内容接口。
